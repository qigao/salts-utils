# SaltsUtils 4.3.0-rc.8

This prerelease adds schema-driven application mappings and native service
dependency injection for CHTTP applications.

## Changes

- `salts_idl_target(SCHEMA_PROJECTION)` exports HTTP/RPC annotation mappings to
  the existing version-1 JSON projection format and generates transport metadata.
- Service-level `inject(member, Interface, header)` generates typed dependency
  records, Component requirements and factories, and instance-bound executions.
  CMeta validates the native receiver signature and its logical Function ABI.
- Method-level `http(verb, route)` declares HTTP routes. Ordered method policies
  remain available through `app_http_policy`; deployment resolves their hooks.
- Native operation catalogs let application hosts assemble services without
  reparsing IDL or duplicating native symbol naming.
- Injection rejects missing/ambiguous/cyclic dependencies at host startup. Native
  borrowed receivers are not admitted to Plugin/Wasm publication or typed-error
  signatures. Existing stateless service signatures are unchanged.

## Dependencies and migration

Use the matching Salts 2.3.0 RC SDK and rebuild generated consumers. The CMake
helper advertises `SaltsUtils_IDL_APPLICATION_VERSION = 2`; CHTTP 2.1.0-rc.3
requires this generator capability. Earlier published SaltsUtils rc.7 does not
provide it.

The experimental `app_inject` and `app_http` spellings are replaced by `inject`
and `http`. Regenerate schemas using the new spellings. Companion annotations
such as `app_http_field`, `app_http_formats`, `app_http_policy` and `app_rpc`
retain their names. The route JSON does not encode dependency or policy metadata;
keep the annotated schema as the application generation source.

Rollback requires restoring the previous generator and generated artifacts
together; applications using injection must also restore their previous hosting
and service signatures.

## Qualification

Local Windows Release validation passed six compiler/projection CTest targets,
two installed C/C++ service consumer tests, three paired CHTTP application tests
and five installed CHTTP consumer tests. Publication additionally requires the
existing six-RID release CI, full Linux/Windows/macOS CTests and package provenance
checks. Android/iOS qualification is build-only, not device execution.
