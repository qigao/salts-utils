# Target Runtime DLL PATH Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run CTest and installed-package consumer executables with DLL search directories derived from each executable's transitive CMake target dependencies, without copying test DLLs or hardcoding dependency roots.

**Architecture:** Raise the source-build floor to CMake 3.27 and use `$<TARGET_RUNTIME_DLL_DIRS:target>` inside the CTest `ENVIRONMENT_MODIFICATION` property. CTest prepends those generated directories to its inherited environment; the inherited `VsDevCmd.bat` PATH remains the sole source of the compiler-injected ASan runtime.

**Tech Stack:** CMake 3.27, CTest, CMake Presets, MSVC AddressSanitizer

**Spec:** `AGENTS.md`

## Global Constraints

- Runtime DLL directories must come from CMake target dependency metadata.
- Do not parse `CMakeUserPresets.json`, query CMake File API, or construct vcpkg/TurboUtils directory layouts.
- Do not copy first-party, vcpkg, or ASan DLLs solely to run tests.
- Disable vcpkg app-local deployment for Windows presets so tests exercise target-derived paths.
- Do not add a configure, build, test, or install preset.
- Preserve Capture's install-time deployment contract for `libyuv.dll` and `jpeg62.dll`.
- Preserve the parent toolchain environment so MSVC ASan remains discoverable without a versioned compiler path.

- [ ] **Step 4: Verify GREEN**
